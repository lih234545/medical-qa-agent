# 医疗问诊 AI Agent — 开发记录（PPT 素材）

> 本文档按开发的真实顺序，完整记录项目的**背景、技术选型、架构设计、核心实现、遇到的问题与解决方案、测试验证**，
> 可直接作为答辩 PPT 的内容骨架。每个小节都可对应 1~2 页 PPT。

---

## 1. 项目背景与目标（PPT：封面 / 项目简介）

- **场景**：构建一个「医疗问诊 AI Agent」，用户可用自然语言咨询疾病、药品、用药等问题。
- **核心诉求**：回答必须**可靠、可溯源、绝不乱说**——只能依据本地权威知识库作答，查不到就拒答。
- **交付形态**：命令行 + Web 两种交互方式。

---

## 2. 需求拆解（PPT：需求分析）

| 需求项 | 说明 |
| --- | --- |
| 本地知识库 | `/data` 下三类数据：疾病百科(JSON)、药品说明书(MD)、医患问答(TXT) |
| 技术栈 | LangChain 开发框架 + FAISS 向量库 + 阿里百炼通义千问 |
| 运行环境 | conda 的 `python-demo` 环境 |
| 交互方式 | ① 命令行 ② 整合 Gradio 的 Web |
| **Agent 规则** | ① 相似度阈值 0.5 过滤；② 仅基于检索结果回答；③ 无结果必须拒答 |

拒答固定话术：
> “抱歉，本地知识库中暂无关于该问题的相关数据，我无法为您提供专业解答。建议您咨询专业医师或查阅权威医疗资料。”

---

## 3. 技术选型（PPT：技术架构）

| 组件 | 选型 | 理由 |
| --- | --- | --- |
| 应用框架 | LangChain 1.x | 生态成熟，内置 Agent / 工具 / 向量库集成 |
| 向量数据库 | FAISS (faiss-cpu) | 轻量、本地、检索快，适合中小规模知识库 |
| 向量化模型 | 通义千问 `text-embedding-v2` | 中文语义表现好，与百炼生态一致 |
| 对话大模型 | 通义千问 `qwen-plus` | 效果/成本均衡；temperature=0 保证严谨 |
| Web 界面 | Gradio `ChatInterface` | 几行代码即可搭出聊天界面 |

**整体流程（RAG）**：
```
用户问题 → Agent → 调用检索工具 → FAISS 相似度检索 → 阈值过滤
      ├─ 命中：把参考资料交给大模型，仅据此组织答案
      └─ 未命中：返回“无结果”标记 → Agent 输出固定拒答话术
```

---

## 4. 项目架构设计（PPT：模块设计）

采用分层、单一职责的模块划分：

- `config.py`：集中管理路径、模型名、阈值、固定文案，便于统一调参与讲解。
- `knowledge_base.py`：**数据处理层**，负责三类数据解析 + FAISS 索引构建/加载。
- `agent.py`：**核心层**，检索工具 + 通义千问 Agent + 严格规则提示词。
- `cli.py` / `web.py`：**交互层**，两种界面共用 `agent.ask()`，避免逻辑重复。
- `main.py`：统一入口，通过参数分发 `build / cli / web`。

> 讲解要点：交互层与核心层解耦 —— 命令行和 Web 只是「壳」，业务逻辑只有一份。

## 5. 核心实现（PPT：关键代码）

### 5.1 三类异构数据的统一处理（难点）

不同格式采用不同解析策略，但最终都转成统一的 LangChain `Document`（正文 + metadata）：

- **JSON（结构化）**：每条疾病记录 → 拼成自然语言文本（疾病名/科室/症状/病因/治疗/禁忌）。
- **Markdown（半结构化）**：按 `## 药品名` 二级标题切分，每种药品 → 一个 Document。
- **TXT（非结构化）**：按空行切分每组 `Q/A` → 一个 Document。

每个 Document 都带 `metadata = {source, category, title}`，用于回答时溯源。
当前版本已扩充为 12 种疾病 + 12 种药品 + 17 组问答 = **41 条文档**。

### 5.2 相似度阈值过滤（Agent 规则①）

向量构建时 `normalize_L2=True` 归一化，使 L2 距离等价于余弦距离：
```
余弦相似度 = 1 - 距离 / 2      # 距离为 FAISS 返回的平方欧氏距离
```
检索后过滤掉相似度 < 0.5 的结果；若全部被过滤 → 返回“无结果”标记。

### 5.3 严格规则的 Agent（规则②③）

用系统提示词把规则固化进 Agent：
1. 回答医疗问题前必须调用检索工具；
2. 只依据工具返回的资料回答，禁止使用预训练知识补充/扩写；
3. 工具返回“无结果”标记时，原样输出固定拒答话术。

Agent 使用 LangChain 1.x 的 `create_agent(llm, tools, system_prompt=...)` 构建。

## 6. 开发中遇到的问题与解决（PPT：亮点 / 踩坑）

> 这部分最能体现工程能力，建议在答辩中重点讲。

### 问题 1：LangChain 版本 API 变更
- **现象**：`from langchain.agents import AgentExecutor, create_tool_calling_agent` 报 `ImportError`。
- **原因**：实训环境安装的是 **LangChain 1.2**，旧的 `AgentExecutor` / `create_tool_calling_agent` 已被移除。
- **解决**：改用新 API `create_agent(model, tools, system_prompt=...)`（基于 LangGraph），
  输入/输出改为 `messages` 消息列表格式。

### 问题 2：相似度阈值不好设定
- **现象**：FAISS 默认返回 L2 距离，数值范围不定，0.5 阈值没有明确意义。
- **解决**：向量归一化（`normalize_L2=True`）后，用 `1 - 距离/2` 换算成 **0~1 的余弦相似度**，
  阈值 0.5 变得直观可解释。

### 问题 3：Windows 控制台中文/emoji 报错
- **现象**：命令行下打印模型回答时报 `UnicodeEncodeError: 'gbk' codec ...`。
- **原因**：Windows 控制台默认 GBK 编码，无法输出 emoji 等字符。
- **解决**：入口处把标准输入输出重设为 UTF-8（`sys.stdout.reconfigure(encoding="utf-8")`）。

## 7. 测试验证（PPT：效果演示 / 测试结论）

在 `python-demo` 环境实测，Agent 表现符合全部规则：

| 问题 | 结果 | 是否符合规则 |
| --- | --- | --- |
| 二甲双胍漏服要补双倍吗？ | 正确回答「不能补双倍」（来源：问答） | ✅ 仅据知识库 |
| 2 型糖尿病典型症状？ | 正确列出症状（来源：疾病百科） | ✅ 命中回答 |
| 孕妇能吃布洛芬吗？ | 正确回答「孕妇禁用」（来源：说明书+问答） | ✅ 命中回答 |
| 氨氯地平什么时间吃？ | 正确回答「早晨服用」（来源：问答） | ✅ 命中回答 |
| 今天北京天气怎么样？ | 输出**固定拒答话术** | ✅ 无结果拒答 |

**结论**：检索命中时严格依据知识库回答；超出知识库范围时准确拒答，未出现臆造。
